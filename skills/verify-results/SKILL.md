# 결과 검증

표·배열·시계열 데이터의 읽기·변환·결합·집계 결과를 검증한다면 [데이터 검사 참조](references/data-checks.md)에서 이번 변경과 관련된 검사만 선택한다.

1. 기존 수용 조건·규칙 사례·도구 시험을 읽고 빠진 기대값만 요구·원자료에서 보완한다. 근거 없이 성공 기준을 바꾸지 않는다.
2. 변경·위험에 관련된 사례를 선택한다. 현재 버전·환경에서 유효한 근거는 재사용하고 무관한 단독 시험·전체 사례를 반복하지 않는다.
3. 실제 입력 → 호출 → 반환 → 규칙 적용 → 결과를 대조한다. 잘못된 값·출처, 빈 결과의 임의 보충, 예시 값 잔류, 필수 단계 누락을 확인한다. 판단 일관성이 우려될 때만 반복한다.
4. 실패하면 기대 X와 실제 Y를 적고 처음 어긋난 단계를 찾는다. 해당 규칙·도구만 고친 뒤 영향받는 흐름을 재검증한다. 성공 조건이 바뀐 경우에만 범위를 다시 정하며 모든 스킬을 재시작하지 않는다.
5. 기존 검증 항목에 실행 결과 → 원인 근거 → 변경·재실행 결과를 남기고 원시 로그는 위치로 연결한다. 미실행·미확인을 구분한다.

과제별 골든셋이 있으면 관련 사례를 재사용한다. 명령형 평가 실행기가 제공되면 해당 도구로 실행하고, 없으면 사용 가능한 검증 방식으로 같은 기준을 확인한다. 입력·소스·기대값 버전이 달라진 이전 통과를 그대로 재사용하지 않는다. 과거 결과 파일의 잔류와 일부 사례만 통과한 상태를 전체 완료로 오인하지 않는다. 단계 전환에 필요한 조건만 한 번 판정해 같은 과제 기록에 반영한다.

현업 답변으로 규칙이 바뀌었다면 그 답변의 출처·적용 범위와 기대값을 연결한다. 확인에 사용한 사례와 별도의 반례·정보 누락 입력을 필요한 만큼 대조하고, 상대의 동의 자체를 실행 검증 통과로 처리하지 않는다.

모델의 첫 결과를 정답으로 복사하지 않는다. 같은 사례의 통과만으로 일반화하지 않는다. 외부 부작용은 재현하려고 중복 실행하지 않는다. 효과 측정이 필요하면 같은 입력·품질 기준에서 검토·수정 시간까지 비교하며, 기준선이 없으면 개선율을 만들지 않는다.

## 변경한 경로의 실행 확인

- **조건부 경로:** 오류 처리·fallback·재시도·캐시·권한 분기 등을 새로 만들거나 바꿨다면, 해당 조건이 실제 호출 흐름에서 도달 가능한지 확인한다. 허용된 테스트 입력·모의 실패로 조건을 발생시키고, 그 분기의 실행과 기대 효과를 assertion·로그·출력 등으로 확인한다. 무관한 테스트 통과나 코드 존재만으로 처리됐다고 보고하지 않는다. 실제 장애·외부 부작용을 일으키는 재현은 피하고, 실행할 수 없으면 미확인 범위와 이유를 남긴다.
- **화면·상호작용:** 화면이나 조작을 바꿨다면 실제 실행 화면에서 변경한 부분과 관련 상태 전환을 확인한다. 빌드·타입 검사 통과는 화면 검증과 구분한다. 현재 환경의 허용 방식으로 실행→관찰→필요한 수정→재확인하며, Cofa 시험에서는 참가자가 플랫폼 Browser에서 직접 조작한다. AI는 코드 검사와 확인 절차를 지원하고, 허용되지 않은 화면 자동 조작·캡처·외부 전송을 추가하지 않는다. 누가 무엇을 확인했는지 기록하며 참가자의 관찰을 AI의 직접 관찰로 표현하지 않는다. 확인할 수 없는 부분은 미확인으로 남긴다.

위 점검은 변경의 영향을 받는 경로에만 적용한다. 기존 검증 기록에 실행 조건·관측·판정을 합치고, 변경이나 새 우려가 없으면 같은 확인을 반복하지 않는다.
