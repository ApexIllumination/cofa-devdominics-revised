# 데이터 읽기·계산 결과 검증

표·배열·시계열 데이터가 결과에 영향을 줄 때 관련 검사만 선택한다. 유효한 단독 시험은 재사용하고 같은 전처리·검증을 다시 구현하지 않는다. 실행 결과는 기존 과제의 검증 기록과 골든셋에 남긴다.

| 위험 | 검증 근거 |
| --- | --- |
| 축·열·레코드 오독 | 실제 전체 입력의 레코드/행/열 수와 원천 위치별 값을 확인. 짧은 기록·길이가 다른 배열·문자형 ID가 보존되는지 대조 |
| 변환 중 손실 | 변환 전후 값·라벨·순서·결측을 가능하면 전체 대조. 표본만 확인했으면 범위와 미확인을 명시 |
| 합산된 필드의 구성값을 다시 더함 | 같은 ID의 원시 기록에서 구성값을 각각 한 번씩 반영해 기대 수치와 판정을 구한다. 이를 모듈의 출력과 최종 설명에 대조한다. 원시 기록이 없으면 해당 대조는 미확인으로 기록한다. |
| 시간/그룹 동일성과 허용오차 혼동 | 계약에 따른 서로 다른 인접값·동일값·감소·그룹 경계의 작은 사례. 통계 수치 허용오차와 입력 동일성 규칙을 따로 적용 |
| 결합 후 합계 부풀림 | 원본 행 수·키별 일치 개수·결합 후 행 수·동일 모집단 가산량 비교. 미등록 제외와 중복 증폭을 각각 확인 |
| 결측을 0으로 오인 | 빈 값·실제 0·분모 0의 대표 행을 끝까지 추적. 보류 목록과 CSV/JSON 표현 확인 |
| 비율의 잘못된 평균 | 분자·분모를 독립 합산해 전체 비율 대조. 행별 평균은 요구가 있을 때 다른 지표로 표시 |
| 미등록·보류 행 소실 | 원본 식별자가 유효 또는 보류 결과에 한 번씩 존재하는지 확인. 사유·원래 값·커버리지 확인 |
| 그럴듯한 고정 출력 | 입력 순서 변경·정상 행 추가·경계 입력에서 관련 결과가 올바르게 변하는지 확인 |

기대값은 실행 전에 규칙·원자료·작은 수동 산식으로 정한다. 가능한 경우 별도 SQL 집계나 독립 계산을 사용하되, 두 구현의 일치만으로 공유한 잘못된 규칙까지 검증했다고 보지 않는다. 분모·모집단과 보류 정책 자체가 과제 요구에 맞는지 먼저 대조한다.

파서 함수의 시험, 실제 원본에서 생성한 산출물, 최종 설명의 수치를 구분해 연결한다. 코드만 작성하고 실행하지 않았거나 예전 출력이 남은 경우를 통과로 처리하지 않는다. 지침과 채점이 다른 해석을 허용하면 규칙을 명확히 한 뒤 새 검사로 기록하고 과거 점수를 소급해 모델 오류로 단정하지 않는다.

실제로 관찰한 실패는 입력/규칙 버전·사례 ID·기대값·실제값·원인·재검증 근거를 과제별 골든셋에 추가한다. 의도적으로 잘못 만든 비교 구현은 학습용 기준선으로 표시하고 실사용 시스템에서 발견한 결함으로 보고하지 않는다. 일부 사례 또는 합성 데이터 통과를 실제 대회·모델 행동의 검증으로 확대하지 않는다.
