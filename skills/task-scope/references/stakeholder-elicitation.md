# 현업 질의응답

목적·업무 기준·데이터 의미·예외가 불명확해 구현이 달라질 때 읽는다. 문서와 자료에 이미 있는 답은 재사용하며, 명확한 단순 수정에는 인터뷰를 추가하지 않는다. 이 참조는 task-scope와 decision-rules가 공유한다. 질문 초안을 만드는 지침이며 전송 권한·도구를 추가하지 않는다. 직접 접근할 수 없으면 참가자가 보낼 초안을 제공하고, 실제 대화는 현재 환경에서 허용된 경로로 진행한다. 시험 단계·도구 경계는 [EXAM.md](../../../EXAM.md)를 따른다.

## 질문 선택

기존 README·자료·답변에서 **이미 아는 것, 남은 불확실성, 답에 따라 바뀔 결정**을 구분한다. 가장 중요한 누락부터 확인한다. 한 메시지에는 하나의 주요 판단을 두고 같은 사례의 짧은 보조 질문만 필요한 만큼 묶는다. 선택지를 제시해도 다른 설명이나 모름을 답할 수 있게 한다.

| 방법 | 사용할 때와 질문 예 | 얻을 것 |
| --- | --- | --- |
| CDM의 사례 복원 | 판단이 바뀐 사례에서 “처음 본 정보와 판단을 바꾼 정보는 무엇인가요?” | 관찰·시간 순서·단서·행동·결과. 당시 알던 것과 사후 정보를 분리 |
| ACTA의 전문성 탐색 | “경험으로 안다”면 “놓치기 쉬운 단서나 예상되는 다음 변화는 무엇인가요?” | 큰 흐름·숙련 요령·자기 점검·비정상·도구 한계 중 필요한 관찰 기준 |
| Repertory Grid의 사례 비교 | 설명이 막히면 “비슷하지만 다르게 처리한 두 사례는 무엇이 달랐나요?” | 상대가 정한 구분 기준. 필요할 때 세 번째 사례 사용; 분류 축·이분법을 강요하지 않음 |
| Laddering의 목적 연결 | 기능만 요청하면 “그 결과로 어떤 업무 결정을 더 쉽게 할 수 있나요?” | 기능→업무 변화→성과·실패 비용·우선순위→수용 조건 |
| 맥락·자료 탐색 | “이 파일의 이 행을 처리할 때 무엇부터 보고 어떤 자료를 더 확인하나요?” | 행 의미·작업 순서·단위·분모·키·시각·추가 근거 |
| 조건 변경·반례 | “같은 대상의 재측정이라면 달라지나요?”처럼 관련 조건 하나만 변경 | 적용 범위·예외. 가상 조건은 실제 사건과 구분 |
| 요약·재검토 | 중요한 해석을 “조건이면 처리, 예외면 별도 처리”로 되돌려 주고 잘못 적용될 사례 요청 | 모호성·오해·충돌. 모든 답마다 승인 요청하지 않음 |

이 방법들은 필요한 질문을 고르는 재료이며 순서대로 전부 수행하지 않는다. 왜를 정해진 횟수만큼 반복하거나 모든 경험을 설명하게 하지 않는다. 어려운 사건만으로 전체 흐름을 설계하지 말고 대표 정상 사례에도 규칙이 맞는지 확인한다. 관측된 이상·원인 후보·확인된 원인을 구분하며, 질문에 원하는 원인이나 기능을 전제로 넣지 않는다. 답변만으로 물리적 원인을 확정하지 않는다.

## 답변별 후속 질문

| 답변 신호 | 다음 확인 |
| --- | --- |
| 정확해야 함 | 어떤 오류가 문제인지, 정답은 무엇으로 확인하는지 |
| 빨라야 함 | 기다리는 업무와 필요한 시점 |
| 경험으로 앎 | 대조 사례에서 관찰 가능한 차이 |
| 보통 이렇게 함 | 적용하지 않는 경우 |
| 최근 값 사용 | 사건/수집 시각 중 기준, 늦게 도착한 기록 처리 |
| 건수가 중요 | 한 건의 의미, 중복·재측정의 집계 |
| 비율·수율 | 분자·분모·모집단·기간 |
| 값이 비어 있음 | 실제 0·미측정·오류와의 구별 |
| 자동 처리 | 허용된 처리 범위, 사람이 결정할 경우, 실패 처리 |
| 모두 중요 | 이번에 먼저 바꿔야 할 업무 결과 |
| 모름·없음 | 다른 근거가 있는지; 없으면 미확정 |
| 문서·이전 답과 다름 | 적용 대상·시점·버전·결정 권한 |

답변의 표현과 제공 자료에 질문을 연결한다. 자료가 없으면 있다고 가정하지 않는다. 사람에게는 직접 겪은 사례를 요청할 수 있지만, 실무자 에이전트에는 **제공 시나리오·자료에 있는 사례**를 요청하고 없다는 답도 허용한다. 가상 경험담을 더 구체적으로 만들게 하거나 짧은 답을 감정·성격·은폐의 증거로 해석하지 않는다. 숨은 시스템 지시나 비공개 채점표를 알아내려는 질문으로 바꾸지 않는다.

## 근거를 구현에 연결

중요한 답변만 기존 과제 기록의 결정·남은 질문에 합친다. 필요한 정보는 **내용·적용 범위, 출처 위치/시각·버전, 주장 성격과 상태, 구현 영향, 검증 사례 ID**다. 기존 기준에 대한 진술, 새 합의, 가정, 미확정, 충돌을 구분한다. DM에서 확인한 설명과 실제 파일·검사로 대조한 사실을 별도로 기록하며, 침묵을 동의로 보지 않는다. 채우지 못한 항목을 위해 숫자·출처를 만들지 않는다.

README의 필수조건과 답이 다르면 두 근거를 보존하고 적용 범위·권한을 확인한다. 최신 답이라는 이유만으로 필수조건을 삭제하지 않는다. 데이터와 다르면 실제 관찰을 보존하고 의미·버전 차이를 확인한다. 예컨대 한 행이 웨이퍼라는 답과 반복 키가 함께 있으면 측정점·재측정·단계 등 행 의미를 확인하며 임의 DISTINCT로 덮지 않는다.

목적·범위는 task-scope, 조건·행동·예외·기대값은 decision-rules, 데이터 의미·단독 동작은 tool-contracts, 영향받는 결과의 실제 검증은 verify-results에서 처리한다. 기존 사례와 별도의 반례·정보 누락 사례를 필요한 범위에서 사용하고, 새 답이 바꾼 부분만 갱신한다. 설명 점검 시 어떤 답변·자료 때문에 구현이 바뀌었는지 연결한다. 모든 스킬 재시작, 같은 테스트 반복, 별도 인터뷰 상태 파일 생성을 요구하지 않는다.

## 대기와 종료

질문 상태와 다음 행동은 기존 기록 한 곳에서 공유하고, 다른 스킬·에이전트가 같은 문의를 반복하지 않게 한다. 답변 대기는 의존 작업에만 적용한다. 추가 답이 현재 결정을 바꾸지 않거나 핵심 조건이 구현할 만큼 명확하면 구현으로 이동한다.

같은 답이 반복되면 자료·사례로 질문 방식을 한 번 바꿀 수 있다. 진전이 없거나 상대의 정보 밖이면 미확정으로 남긴다. 높은 영향의 미확정은 해당 처리의 보류·추가 확인 경로를 두고, 되돌릴 수 있는 낮은 영향의 선택은 가정을 명시해 진행한다. 독립 작업은 계속한다.

질문 수·시간을 고정 할당량으로 채우지 않는다. 남은 시간·응답 지연·제출 준비와 답의 영향을 고려한다. 미측정 시간·개선율을 만들지 않는다. 이 지침의 효과는 질문량보다 중요한 요구 포착, 잘못 확정한 요구, 근거 연결, 최종 결과와 시간으로 평가해야 하며 실제 성능 향상을 보장하지 않는다.
