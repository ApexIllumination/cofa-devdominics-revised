# 업무 판단 규칙

현업자의 판단 단서·암묵적 기준·예외가 불명확하면 task-scope와 공유하는 [질의응답 참조](../task-scope/references/stakeholder-elicitation.md)에서 필요한 질문만 선택한다. 기존 답변과 근거를 재사용하고 새 인터뷰를 자동 시작하지 않는다.

1. 제공 규정과 사례를 읽는다. 필요한 경우에만 최근 실패나 숙련자와 초보자의 판단 차이를 확인한다.
2. 입력 조건, 참·거짓일 때의 행동, 예외·정보 누락·규칙 충돌의 처리와 우선순위를 적는다.
3. 근거와 적용 범위를 기록한다. 공식·사용자 확인·경험상 임시 기준을 구분하고 예제 수치를 실제 임계값으로 가져오지 않는다.
4. 정확한 수치 비교·고정 분기는 코드로 표현하고, 문맥 해석이 필요한 부분을 구분한다.
5. 필요한 일반·누락·핵심 예외 사례의 입력과 기대 결과를 명세한다. 유효한 사례는 재사용한다. 실제 실행·판정은 검증 단계에서 한 번 수행한다.

반복 검증할 사례는 그 과제의 골든셋에 모아 사례 ID·입력 버전·필수 결과·금지 결과·근거를 연결한다. 판정에 맞추기 위해 실행 후 기대값을 낮추지 않는다. 기존 사례와 변형 사례를 구분해 과적합 여부도 확인한다.

종료 결과는 규칙·근거·예외·기대값이다. 과제 고유의 규칙과 임계값은 과제 설정·기록에 둔다. 재사용·설치된 스킬은 자동 수정하지 않고, 스킬 개선을 요청받은 경우에만 고친다. 중복 스킬 버전을 동시에 유지하지 않으며 ‘의심’을 근거 없이 ‘확정 위반’으로 바꾸지 않는다.

## 수치 경계와 범위가 있는 예외

경계에서 결과가 바뀌면 단위·측정 해상도·경계 포함 여부와 근거를 먼저 확정한다. “최대”의 의미가 불분명하면 같은 입력이 경계에 정확히 걸릴 때 허용하는지 현업에 묻는다. 예외는 면제하는 규칙을 이름으로 지목하고, 독립적인 필수 제약은 계속 검사한다.

한 수치 규칙과 예외 하나가 독립 제약과 겹치면 [경계 사례 생성기](scripts/boundary_matrix.py)에 합의된 JSON을 주어 골든셋 후보를 만든다. 예를 들어 `{"rule":"duration","operator":"<=","limit":30,"step":1,"unit":"min","exception":"approved_delay","retained_rule":"capacity","source":"DM-2"}`를 policy.json에 저장하고 `python3 scripts/boundary_matrix.py policy.json`을 이 스킬 디렉터리에서 실행한다. 정수 눈금만 지원한다. 소수 단위는 실제 업무 해상도에 맞춰 정수로 변환한다.

출력은 바로 아래·같음·바로 위 × 예외 유무 × 독립 제약 위반 유무의 12개 기대 판정이다. 각 행을 과제의 실제 입력으로 변환해 기존 eval로 실행한다. 서비스가 거절 사유까지 반환하면 사유도 대조한다. 필수 정책이나 예외의 적용 범위가 미정이면 기대값부터 만들지 않는다.
