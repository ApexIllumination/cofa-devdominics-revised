# UI 작업에서 Impeccable 사용하기

사용자가 새 화면을 설계하거나 기존 화면의 비교·탐색·입력 흐름을 개선하려고 할 때 사용한다. 먼저 **누가 이 화면에서 어떤 결정을 내리는지**, 바꿀 화면 하나, 유지할 업무 규칙을 정한다. 이미 과제에서 확인한 내용은 그대로 사용한다.

1. **연결한다.** Codex에서 사용 가능한 스킬에 `impeccable`이 있으면 그 스킬을 호출한다. 자료 준비 명령을 실행했다면 출력된 `.design-tools/impeccable/<commit>/SKILL.md`를 읽는다. 별도 체크아웃을 사용하는 경우에는 사용자가 지정한 위치나 과제 프로젝트의 `.agents/skills/impeccable/SKILL.md`를 읽고, 해당 버전의 실행 안내를 따른다. 엔진의 작업 디렉터리는 화면을 만드는 프로젝트다. 이전 벤치마크의 작업 폴더를 현재 프로젝트로 사용하지 않는다.
2. **한 가지 작업을 맡긴다.** 새 화면이면 사용자와 핵심 행동을 전달해 설계를 요청한다. 기존 화면이면 비교하기 어려운 항목, 불분명한 상태 또는 잘 보이지 않는 조작 중 실제 문제 하나를 골라 리뷰한다. 기존 컴포넌트·디자인 토큰·한국어 용어를 전달한다. 업무 기준이 모호해지면 [decision-rules](../skills/decision-rules/SKILL.md)로 돌아간다.
3. **제품에서 확인한다.** 반영한 변경은 [verify-results](../skills/verify-results/SKILL.md)로 넘긴다. 셔틀 비교라면 두 안을 키보드로 선택하고 좁은 화면에서도 헤더와 값의 대응이 유지되는지, 선택 불가 사유가 보이는지 확인한다. 비교 기준·단위와 엔진 결과도 대조한다. 화면을 직접 확인할 수 없으면 실제로 확인한 범위까지만 기록한다.

스킬이 없으면 기존 프런트엔드 구성으로 진행한다. 별도 설치를 원하는 프로젝트는 [공식 설치 안내](https://impeccable.style/docs)를 따른다. 자료 준비 명령은 스킬 디렉터리를 저장한다. 실행 엔진을 처음 호출할 때는 플랫폼별 바이너리 다운로드가 추가로 필요할 수 있다. 시험 환경에서는 [EXAM.md](../EXAM.md)의 도구·화면 확인 범위를 우선한다.

**대화 예시**

> 셔틀 노선 비교 화면에서 HR이 두 안의 비용과 초과 통근시간을 한눈에 비교하게 해 줘. Impeccable을 사용할 수 있으면 현재 화면의 정보 배치를 먼저 검토해. 정원과 +15분 판정은 기존 엔진을 따르고, 수정 뒤에는 모바일과 키보드로 두 안을 선택하는 흐름을 확인해 줘.

특정 컴포넌트 상태·키보드 탐색·모션만 점검하려면 [외부 UI 스킬 선택표](ui-tools.md)에서 해당 작업으로 이동한다.
