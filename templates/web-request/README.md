# 조회 버튼과 API 응답

버튼을 누르면 조회 중에는 두 번째 요청을 막는다. 서버 오류가 나면 이전 값을 내리고 같은 버튼을 ‘다시 시도’로 바꾼다. 다시 눌러 성공하면 결과를 보여준다. 사용 중 로그인이 풀리면 로그인 화면으로 돌아간다.

기존 React + TypeScript 앱에 `api.ts`, `ReadPanel.tsx`를 함께 복사한다. 같은 출처의 쿠키 세션용이다. 이미 쓰는 데이터 조회 라이브러리가 있다면 교체할 필요 없이 아래 동작만 대조한다.

- 로그인·로그아웃: `await postJson(path, body)`. 204에는 본문이 없으므로 JSON으로 읽지 않는다. 로그인 성공 뒤에는 `/api/me`로 사용자 ID를 받고 업무 데이터는 별도 경로에서 읽는다.
- 조회: 로그인한 화면에서 `ReadPanel`에 계정 ID, API 경로, 버튼 이름, 응답 검사 함수(`decode`), 401 처리 함수, 결과 표시 함수를 준다. 빈 배열 등 유효한 빈 결과는 표시 함수에서 “항목 없음”으로 그린다. [동작 예제](../web-smoke/example/app.tsx) 참고.
- `onUnauthorized`에서는 부모의 로그인 상태와 사용자별 캐시를 지운다. 컴포넌트는 계정이나 경로가 바뀌면 자체 결과를 버리고 진행 중인 조회를 취소한다. 접근 권한은 서버가 매 요청 확인해야 한다.
- 다시 시도 버튼은 읽기(GET) 전용이다. 저장·배차 확정처럼 중복 실행이 문제가 되는 요청은 실패해도 자동으로 다시 보내지 않는다.

코드 흐름: 조회 버튼 → ReadPanel → getJson → 서버 → decode → 결과 표시(401이면 부모 로그인 상태 해제).
